## 三、三项必须回传的发现（都与预期不符）

### 1. 红线分母 = 1，红线只由 real_b.txt 一份撑着

`real_a.txt`（现口径 42.50）与 `real_c.txt`（39.11）本来就在 55 以下，**永远不会「穿越」**。
所以「真实件穿越=0」实际等价于「real_b.txt ≥ 55」，是一份简历的判据。

### 2. 红线不构成约束 —— γ 不是由红线定的

把 γ 一路推到 0.75，红线依然可满足（只要 scale 抬到 55）。红线真正咬住的是
**它和「放行 ∈ [65,75]」通过 scale 这根旋钮互斥**：

| γ | 红线最小可行 scale | 该 scale 下放行 | 放行∈[65,75] 的 scale |
|---|---|---|---|
| 0.00 | 20 | — | 25 |
| 0.10 | 22 | — | 25, 27 |
| 0.20 | 27 | 70 | 27 |
| 0.25 | 30 | 76 | **无** |
| 0.50 | 45 | — | 无 |
| 0.75 | 55 | — | 无 |

→ **保放行带 → γ 上限 0.20**；不再保放行带 → γ 可到 0.25（放行 76）或更高。
「取满足红线的最大 γ」这个指令里，红线并不绑定，绑定的是放行带。

### 3. 红线余量 < 实测分数抖动，所以「穿越=0」是险过，不是稳过

`out/crossline2.log` 实测同配置重复跑：**分数极差中位 1.0 分、最大 3.2 分**。

| 候选 | 红线余量 | 与抖动的比较 |
|---|---|---|
| γ=0.20 / s=27（用户规则下的最大可行 γ） | **+0.13** | 远小于抖动中位 → **重跑一次就可能破线** |
| γ=0.25 / s=30 | +0.24 | 同上 |
| γ=0.05 / s=25 | +1.65 | ≈ 抖动中位，仍不宽裕 |
| γ=0.00 / s=25 | +2.33 | 仍 < 抖动最大 3.2 |

**在 γ∈[0,0.25] 内，没有任何组合能同时做到「红线余量 > 抖动最大 3.2」与「放行 ≤ 75」**：
要余量 ≥3 得把 scale 抬到 30+（γ=0 时放行 80、γ=0.1 时 85）。
→ 红线目前是靠运气过的。这是本轮最需要裁决的一点。

## 十一、四判据交集：**加上「明显−边缘」就无解**

把 判据①红线 + ②ρ + ③重叠 + ④误放 一起扫（6 γ × 8 变体 × 33 scale）：

**交集只有 2 个点**：

| 点 | 最小余量 | 重叠 | 误放 | **明显−边缘** | 放行 / 转人工 / 自动淘汰 |
|---|---|---|---|---|---|
| γ=0.00 · nb=8 · scale=22 | +3.76 | 0.73 | 0 | **9.6** ❌ | 27 / 109 / 174 |
| γ=0.05 · nb=8 · scale=24 | +3.68 | 0.73 | 0 | **11.5** ❌ | 35 / 103 / 172 |
| （现临时点 γ=0.05·W1·s=25 对照） | **−3.65** ❌ | 0.92 | 0 | 20.4 ✅ | 68 / 57 / 185 |
| （现口径基线） | — | — | — | — | 74 / 57 / 179 |

**结论：加上「明显−边缘 >15」这一条，那 2 个窄缝交集点也被挤掉，四判据交集为空。**

### 成因：**scale 方向冲突**，不是判据本身有矛盾

同一根 scale 旋钮被两个方向抢：

- **红线判据 B 要高 scale** —— 把去数字版抬过 58.2；
- **三判据（ρ / 重叠 / 误放）要低 scale** —— 排序贴近基础项才有高重叠、零误放。

**「明显−边缘」站在高 scale 那一侧**，所以它一旦入列，就把那 2 个窄缝交集点也挤掉了。

**准确表述：「红线 + 明显−边缘」与「重叠/误放」互斥，不是「红线」与「明显−边缘」互斥。**
证据：W2 在 **γ=0.20 / scale=47** 同时满足**余量 +3.28** 与**明显−边缘 20.0**（>20），
但该点 **重叠 0.61、误放 27** —— 卡住它的是重叠与误放，不是红线，也不是明显−边缘。

> **结论：当前口径下自动校准不可用，真实动线只能走人工锚点标定（anchor_calibrated）。**
> 成因记为「**scale 方向冲突**」，不记为「判据自相矛盾」。
