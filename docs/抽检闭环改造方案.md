# 抽检闭环改造方案（待定，等线 70 下的转人工队列件数）

> 背景：现在的抽检闭环**结构性空转**——`review.pool()` 只抽"自动淘汰件"，而冷启动**不做自动淘汰**，
> 实测池子 = **0 件** → 攒不出人工标注 → 自动校准永远卡在"样本不足"。
> **空转比关掉更危险**：日志和界面看起来"闭环已就绪"，实际一条样本都进不来，会误导后续判断。

## 一、先量，再定（判据）

全量重跑后跑一次 `out/line_sweep_report.py`，看**转人工队列的实际件数**：

| 转人工队列 | 建议 |
|---|---|
| ≥ 100 件 | **路线 A**：从转人工队列按优先级抽样，正式开启复核闭环 |
| < 100 件 | **路线 B**：显式标记 `calibration_status = "disabled_cold_start"`，等自动淘汰开启后再开 |

理由：抽样的意义在于"用少量人工覆盖高风险段"。几十件时抽样等于全看，人工负担不比全看小，
却会让人误以为"闭环在转"。

## 二、路线 A：从转人工队列按优先级抽样

**核心改动**：抽检池从"只有自动淘汰件"改成"两类来源，各自带标记"。

1. **两个池子、一个抽取器，标记位区分**（不复制数据，避免双写漂移）：
   - `source='auto_reject'`：原设计（漏放风险的直接来源）——冷启动下为空
   - `source='manual_review'`：新增，按**优先级排序**抽：
     1) 靠近线的一批（|score − 线| ≤ 2，最可能被判错）
     2) 模型内部打架的（`conflicts` 含 `llm_vs_rule` / `fit_vs_verdict` / `edge_band`）
     3) 硬门槛 unknown 的（证据不足，人工最容易补判）
     4) 其余按分数降序
2. **分层配额**：擦线带 50% / 中间带 10% / 远端 3%（沿用已定的分层抽检参数），
   但对**转人工件**的语义不同——这里的"误放"风险是"系统判转人工、其实该直接放"，所以
   **抽检结论要能双向用**：`pass` = 复核认为可以过；`reject` = 复核认为确实不该过。
3. **标记位**（新增列，别复用 `action` 语义）：
   - `spot_check_item.source`：`auto_reject` / `manual_review`
   - `spot_check_item.calibration_eligible`：只有**自动化淘汰的复核结论**才进自动校准样本池
     （转人工件的复核结论不进——它不是"系统的漏放"，而是"系统没能自动判断"，混进去会把线拉歪）
4. **纪律不变**（已有实现，别改坏）：
   - 抽过不再抽；不累加（旧批次未复核项标 `expired`）；**未复核不算被抽过**
   - 通过 = 系统判错了 → 记人工标注 + 按天归档；淘汰 = 系统判对了 → 进人工淘汰库
   - 当日"系统判淘汰 / HR 判该留" ≥ 2 条 → 提示可以触发校准

## 三、路线 B：显式关闭（cold start）

1. `calibration` 表加一个状态：`calibration_status ∈ {active, disabled_cold_start}`。
2. 关闭时：
   - `review.draw()` 明确返回 `{"status": "disabled_cold_start", "reason": "...", "auto_reject_pool": 0}`，
     **不假装抽了 0 条**
   - 界面/报告里显示一行灰字："复核闭环未启用（冷启动：不做自动淘汰 → 无淘汰件可抽）"
   - 自动校准入口直接拒绝执行并写原因（现在是"样本不足"，语义不对）
3. 开启条件写死：`auto_reject_enabled = true` **且** 稳定性记录危险侧翻转率为 0。

## 四、不改的东西

- 抽检的三条纪律、归档规则、校准的两条防抖约束（正负样本各 ≥3、两组分数必须分得开）都不动。
- 不为"让日志好看"而放宽任何判据。

## 五、落地顺序

1. 全量重跑结束 → 跑 `out/line_sweep_report.py` 拿转人工件数
2. 按上表选路线 A 或 B
3. 实现后**用真实数据验收**：抽取器输出的分层配额是否符合预期、标记位是否两类都能区分、
   关闭态是否是"显式原因"而不是静默空结果
