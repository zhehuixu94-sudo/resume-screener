# 等分制 vs 现口径 · 同批对照（2026-09-18）

只读、0 token。在**同一批落库的模型输出**上重算，隔离模型波动，只看口径差异。
复现：`out/compare_visions.py --line 60 --band 5` · `tools/equal_split_sweep.py --job config/job_hr_admin.json`

## 一、两套口径是什么

| | 现口径（生产） | 等分制（`equal_split.py`，未接生产） |
|---|---|---|
| 基础项 | `60 × Σ((维度权重/权重和) × 该维最强相关度)`，权重 30/25/20/15/10 **是拍出来的** | `每项基础分 = 及格分60 ÷ 及格项数N`，`项得分 = 基础分 × 相似度 × 难度` |
| 及格语义 | 无。分数高就是好 | **满足全部及格项 = 恰好及格分**；难度中=1.0基准，高=1.5，低=0.5 → 上限 60×1.5=90 |
| 权重争议 | 靠拍 | 被「**及格项清单**」取代（可人工勾选） |

## 二、结果：等分制把现口径已有的结构抹平了

```
现口径（0~100）                      等分制（0~90）
  20~30   36 ████████                  20~30   61 ██████████
  30~40   53 ████████████              30~40  107 ███████████████████
  40~50   63 ██████████████            40~50   78 ██████████████
  50~60   52 ████████████              50~60   55 ██████████
  60~70   31 ███████                   60~70    4 █
  70~80   65 ███████████████  ← 高分簇  70~80    1 █
  80~90    9 ██                        80~90    0
```

| | 中位 | 均值 | 标准差 | 范围 |
|---|---|---|---|---|
| 现口径 | 50.25 | 52.15 | **17.82** | 18.82~81.14 |
| 等分制 | 38.20 | 39.19 | **10.87** | 15.08~72.00 |

- 两者 ρ = **+0.689**
- **现口径是双峰**（20~60 的主团 + 70~90 的 74 件高分簇，中间 60~70 只有 31 件）
- **等分制是单峰且更集中**（σ 10.87 vs 17.82），60 分以上只剩 **5 件**

> ⚠️ 这与 `equal_split.py` docstring 的预期相反。它声称现口径「总分天然往中间挤、单峰」，
> 实测现口径反而**有**双峰结构，而等分制把它抹平了。

## 四、根因：及格项清单是占位值，等分制在空转

`basic_items_of(job)` 返回**所有 weight>0 的维度**（= 全部 5 维）。等于把"及格"定义成"5 维全强×中"。

而各及格项实测：

| 及格项 | 平均得分 / 满配 12 | 零分份数 |
|---|---|---|
| admin | 8.5 | 18 |
| **hr_ops** | **6.0** | **120（39%）** |
| comm | 8.0 | 0 |
| office2 | 8.8 | 2 |
| attitude | 7.9 | 20 |

`hr_ops`（人事/档案/考勤，岗位核心）**120 份零分** → 几乎没人能 5 项全满 → 没人过 60 线 → 自动通过恒为 1。

**这套机制真正的开关是「及格项清单」，而它在系统里从来没被定义过**（`basic_item_label` 表 **0 行**，
代码里只有一句"将来 HR 在界面上勾「基本项」时，这里换成勾选结果"的注释）。

## 五、结论

1. **跑通**：等分制在 hr_admin 310 份上端到端跑完，新旧 diff 拿到（本节即是）。
2. **但结论是负面的**：占位清单下等分制**更集中、单峰、几乎没有自动通过**，并抹平了现口径已有的高分簇。
3. **不能据此判定等分制不好** —— 它跑的是空转态。要判定它，必须先有**及格项清单**。
4. **清单只能由人定**（HR，或在无 HR 时由项目负责人定）：哪些维度是"必须满足"、哪些只是加分。
   系统不该猜这个 —— 猜出来又是一套拍出来的权重。

**下一步候选**（待定）：
- (a) 定义一份及格项清单（例如只取 admin + hr_ops 为核心及格项，其余列入加分），重跑等分制看分布是否出现结构；
- (b) 把 `basic_item_label` 表接上（读+写），让清单成为配置而不是代码常量；
- (c) 承认两套口径都缺"标准"，先补标准再谈哪个口径好。
